## 可回看的决策

开发过程中替用户做的小决定。如果用起来不合适，可以改。

| 决策 | 理由 | 改起来的代价 |
| --- | --- | --- |
| 讲师最多 6 位 | 两行、每行 3 张肖像卡片，排得下 | 改 `training-form.js` 的 `MAX_SPEAKERS` 和 `training_extract.MAX_SPEAKERS` |
| 姓名、头衔、资历、照片都为空的讲师卡不写进提示词 | HR 经常留着默认的空白卡片 | 小 |
| 「仅文字」模式下，只有照片的讲师不算讲师 | 文字模式本来就不画人像 | 小 |
| 封面提示词只在比例变化时重拼 | 封面提示词和生图接口无关，避免出现多余的提示条 | 小 |
| 生成时的提醒（如肖像被舍弃）和完成提示一起常驻显示，点击才关闭 | 怕用户错过 | 小 |
| AI 识别：原文只截前 2 万字；不支持 .doc 和 PDF | 控制成本，不引入额外依赖 | 中 |
| AI 识别结果替换整张表单，呈现方式不变，同名讲师保留肖像 | 用户选择了整表替换；呈现方式和照片原文里不会有 | 小 |
| AI 识别：原文只写了月日时，取今天之后最近的那一天 | 通知里通常不写年份 | 改 `_system_prompt` |
| 文本模型默认 `qwen-plus`，关闭思考模式 | 支持结构化输出，质量和成本比较均衡；思考模式下不支持结构化输出 | 在设置里改模型名即可 |
| 删除了旧的「init 示例提示词加载」测试 | 那个功能随电商示例一起删了 | 无 |
