# 接手指南

## 1. 这是什么

本地运行的 AI 海报工作台：**生成图片 → 拆成透明图层 → 拖动、缩放、调整叠放 → 导出**。

- **主要用户**：企业人力资源部、培训部门，大多不是设计师。
- **三个品类**：
  - **封面图**：从 31 种 Punk 风格里看图选一个。
  - **培训海报**：在弹窗里填培训信息，或用「AI 识别填入」从通知文件里自动提取。
  - **自由创作**：直接写提示词。
- **模型**：
  - 生图默认用阿里云百炼的千问，支持讲师肖像参考图；也可以切换成蚂蚁数科 MaaS。
  - 拆层固定用 MaaS。
  - AI 识别用千问文本模型。
- **来历**：基于开源项目 Cover Studio（同级目录 `../cover-studio`）二次开发；千问接入和培训海报提示词参考了 `../ref培训海报生成器`。

## 2. 10 分钟跑起来

1. 准备 Python 3.10 及以上版本。后端只用标准库，**不需要 `pip install`**。如果要跑前端测试，再装 Node 20 及以上版本。
2. 启动：Windows 双击 `启动.bat`，或在命令行执行 `python server.py --open`，会打开 http://127.0.0.1:8765 。
3. 不填 Key 也能先点「载入示例」，体验示例海报的 8 个图层，看看编辑器怎么用。
4. 要真正生成和拆层，在右上角「API 设置」里填：
   - 千问 API Key（百炼控制台获取），用于生图和 AI 识别；
   - MaaS API Key，用于拆层。
   - 更方便的做法：把 `.env.example` 复制为 `.env`，填入两个 Key（以及想改的模型、地址、端口），刷新页面就会自动载入。`.env` 已在 `.gitignore` 里，不会被提交。
5. 跑一遍测试，确认环境正常（都不会调用付费接口）：

   ```bash
   python -m unittest test_server.py test_qwen.py test_extract.py test_edits.py
   node test_training.cjs && node test_editor_core.cjs && node test_app.cjs
   ```

## 3. 阅读代码的顺序

1. `server.py`：从 `Handler.do_POST` 看起，先弄清楚 `/api/jobs` 和 `/api/extract` 两条链路。
2. `static/training-prompt.js`：纯函数，表单内容进去，提示词出来。最好读，也最能说明这个产品在做什么。
3. `static/app.js` 前 200 行：品类、弹窗、API 设置、提示词一致性的核心逻辑。
4. `static/app.js` 里的 `jobPayload` 和 `submit`：提交任务的过程。
5. 图层编辑器（`app.js` 后半部分）基本沿用 Cover Studio，暂时不需要改时可以跳过。

配合 [技术架构](技术架构.md) 一起看。

## 4. 最容易踩的坑

1. **改了 Python 文件必须重启服务。** 旧服务遇到新接口只会返回「接口不存在」。只改前端文件时，浏览器按 `Ctrl + F5` 刷新即可。
2. **页面的安全策略禁止内联样式和脚本。** 不能写 `style="..."` 或内联 `<script>`，样式一律走 class。
3. **前端测试是按字符串截取 `app.js` 片段来跑的。** 改函数名、或者新写一个同名的 `const snapshot=` 之类的语句，测试就会截错代码。标记清单见 [开发规范](开发规范.md#测试规范)。
4. **提示词里写的讲师肖像必须和实际发送的一致。** 判断该发哪些肖像只能走 `TrainingPoster.compile` 返回的 `references`，不要另写一套。
5. **中文 Windows 的编码问题。** 读写文件一定要写 `encoding='utf-8'`。原版 Cover Studio 的素材库就是因为没写这个，在中文 Windows 上读不出来。
6. **千问接入里有几条是实测得来的结论**（百炼官方域名必须走原生接口、HTTP 200 也可能是失败等），改之前先读 [技术架构 · 千问生图](技术架构.md#千问生图)。
7. **mock 网络请求时**，`server` 和 `qwen_client` 共用同一个 `urllib.request` 模块。同一个测试里要模拟多次调用，用一个 patch 加 `side_effect=[…]` 按顺序返回。
8. **弹窗是模态的。** 弹窗打开期间，页面其他部分不能操作，所以不能在弹窗里引导用户去点别的面板。

## 5. 关键决策及原因

| 决策 | 原因 |
| --- | --- |
| 后端用 Python 标准库，不迁到 Node | 用户选的；保留 Cover Studio 的服务端结构，部署时只需要装 Python |
| 只做本地版本，删掉 Cloudflare 部署 | 当前阶段不接服务器，Key 和数据都留在本机 |
| 生图和拆层分开配置（生图用千问，拆层用 MaaS） | 千问支持讲师肖像参考图，但没有拆层能力 |
| 培训海报不让用户选视觉风格和版式 | HR 不是设计师，交给 AI 判断，表单保持简短 |
| 文字一律画进海报，不留白 | 拆层后文字本来就是独立图层，可以单独挪动 |
| 设置区用弹窗，保存后才更新提示词 | 用户要求；同时方便做「覆盖手改前先确认」 |
| AI 识别结果替换整张表单 | 表单默认带示例数据，只填空白项会把示例内容混进来；用户选择了这个方案 |
| 去掉小红书品类和电商示例 | 用户群体是企业内部培训 |

更多由开发者替用户做的小决策，见 [问题待办 · 可回看的决策](问题待办.md#可回看的决策)。

## 6. 接手后可以先做的事

[问题待办](问题待办.md) 里标了优先级，适合上手的有：

- 本机服务是旧版本时，给出明确的「请重启」提示（只改前端，改动小）。
- 补 `.gitattributes`，让 `启动.bat` 在 git 里保持 CRLF 换行。
- 用 `../培训通知样例/` 里的 5 份样例实测 AI 识别，根据结果调整提示词。
