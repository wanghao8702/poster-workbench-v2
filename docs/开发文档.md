# 海报工作台 V2 · 开发文档

面向接手维护和继续开发的人。使用说明见根目录 `README.md`。

> 本文描述的是**当前代码**。`docs/specs/` 和 `docs/plans/` 是第一版开发时的设计文档和实施计划，记录了当时的决策过程，后来又陆续加了风格图片选择、清空画布、AI 识别填入等功能，细节以本文和代码为准。

---

## 1. 项目是什么

本地运行的 AI 海报工作台：**生成图片 → 拆成透明图层 → 拖动、缩放、调整叠放 → 导出**。主要用户是企业 HR 和培训部门，也能做文章封面和自由创作。

- 基于开源项目 Cover Studio（同级目录 `../cover-studio`）二次开发；千问接入和培训海报提示词逻辑参考了 `../ref培训海报生成器`。
- **只做本地版本**：Python 服务只监听 `127.0.0.1`，没有账号体系，也不做线上部署（原项目的 Cloudflare 部署已删除）。

## 2. 技术栈与运行

| 部分 | 技术 | 约束 |
| --- | --- | --- |
| 后端 | Python 3.10+，**只用标准库** | 不要引入 pip 依赖；目标用户的电脑只装了 Python |
| 前端 | 原生 HTML / CSS / JS | 无构建步骤、无框架、无第三方库 |
| 测试 | Python `unittest`、Node 20+ 跑 `.cjs` 脚本 | Node 只用于测试，运行时不需要 |

```bash
python server.py --open        # 默认端口 8765；--port 8770 换端口
```

Windows 用户双击 `启动.bat`，它会依次尝试 `py -3`、`python`、`python3`。

**改完 `server.py`、`qwen_client.py` 或 `training_extract.py` 后，必须重启服务**，Python 不会热加载。只改 `static/` 下的文件时，浏览器按 `Ctrl + F5` 刷新即可。旧服务遇到新接口会返回「接口不存在」，这是最常见的「明明改了却不生效」的原因。

## 4. 整体流程

```text
浏览器 (static/*)                          本机服务 (server.py)                   上游
──────────────────                        ───────────────────                    ────
弹窗表单 ──compile──▶ 完整提示词
   │                     │
   │            POST /api/jobs {kind:generate, provider, references…}
   │                     ├────────────▶ validate_job_payload ─▶ 线程池 run_job ─┬▶ 千问 qwen_client.request_image
   │                     │                                                    └▶ MaaS /images/generations
   │            GET /api/jobs/<id>（每 1.5 秒轮询）◀── JOBS 内存表
   │                     ▼
   │            画布预览 ──「继续拆解」──▶ POST /api/jobs {kind:split, image} ─▶ MaaS /images/edits
   │                                                                               │
   │            图层编辑器 ◀──────── output/<id>/layer-*.png ◀────────────────────┘
   │
   └─ AI 识别填入 ── POST /api/extract（同步）──▶ training_extract ─▶ 千问文本模型（OpenAI 兼容）
```

- 生成和拆层是**异步任务**：提交后拿到任务 id，前端轮询；最多同时跑 2 个，超时等待 12 分钟。
- AI 识别是**同步请求**，一般 5–20 秒返回。

## 5. 后端

### 5.1 路由（`server.py` 的 `Handler`）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET | `/api/config` | `{runtime, default_key, default_qwen_key}`，读 `.local-key` / `.local-qwen-key` |
| GET | `/api/assets` | 素材库列表，扫描 `output/*/manifest.json` |
| GET | `/api/jobs/<id>` | 任务状态 |
| POST | `/api/jobs` | 提交生成或拆层任务，返回 202 和任务 id |
| POST | `/api/extract` | AI 识别填入，同步返回 `{values, chars, truncated}` |
| POST | `/api/assets/delete`、`/api/assets/restore` | 素材移入或移出 `output/.trash/` |
| GET | 其他路径 | 静态文件（`static/`）或产物（`/output/...`），带路径穿越检查 |

安全约束（**不要放宽**）：

- 只监听 `127.0.0.1`；`local_request()` 校验 Host 和 Origin，挡住其他网页的跨站请求。
- 响应带 CSP：`default-src 'self'`，**不允许内联脚本和内联 style 属性**。前端新代码不能写 `style="..."` 或 `<script>` 内联代码，样式一律走 class。
- 请求体上限 `MAX_BODY = 64 MB`（多张讲师肖像要用）。
- 不记录访问日志（`log_message` 被置空），避免泄露 Key 和图片地址。

### 5.2 `/api/jobs` 请求体

```jsonc
// 生成 · MaaS
{"kind":"generate","provider":"maas","key":"<MaaS key>","prompt":"…","ratio":"3:4"}
// 生成 · 千问（培训海报可带讲师肖像）
{"kind":"generate","provider":"qwen","key":"<百炼 key>","prompt":"…","ratio":"3:4",
 "model":"qwen-image-3.0-pro","base_url":"https://dashscope.aliyuncs.com/api/v1",
 "purpose":"training","references":[{"name":"林悦.jpg","data":"data:image/jpeg;base64,…"}]}
// 拆层（固定 MaaS）
{"kind":"split","provider":"maas","key":"<MaaS key>","prompt":"<图层规划>","ratio":"auto","image":"data:image/png;base64,…"}
```

校验集中在 `validate_job_payload()`：比例白名单 `RATIOS`、品类白名单 `PURPOSES`、模型名正则、Base URL 必须是 https、参考图最多 10 张且必须是 PNG/JPEG/WebP。

### 5.3 任务与产物

`run_job()` 在线程池里执行，状态写进内存字典 `JOBS`（`queued → running → done / error`）。服务重启后 `JOBS` 清空，但素材库从磁盘读取，不受影响。

每个任务一个目录 `output/<任务id>/`：

| 文件 | 说明 |
| --- | --- |
| `image-01.png` 或 `layer-01..N.png` | 生成结果或拆出的图层 |
| `source.png` | 拆层时的原图 |
| `ref-01.jpg …` | 千问生成时使用的讲师肖像，仅留档，不进 ZIP |
| `manifest.json` | `kind, provider, model, ratio, prompt, images[], source_name, warnings, elapsed, usage, created_at` |
| `prompt.txt`、`images.zip` | 提示词和打包下载 |

兼容性：旧记录（原 Cover Studio 生成的）没有 `provider` 和 `model` 字段，`list_assets()` 会退回默认模型名，**改 manifest 结构时要继续兼容旧记录**（有测试 `test_lists_legacy_manifest`）。

### 5.4 千问生图（`qwen_client.py`）

移植自 `ref培训海报生成器/ai-proxy.js`，其中几条是实测得出的结论，**不要随意改动**：

- `detect_protocol()`：Base URL 含 `/api/v1` 时走**百炼原生 DashScope 接口**；百炼官方域名的 `compatible-mode` 地址配图像模型时，也要改走原生接口，因为兼容模式没有 `/images/generations`，会返回 404。
- 原生接口**可能 HTTP 200 却在正文里返回 `code` 和 `message` 表示失败**，所以要检查正文。
- 原生接口返回的是 24 小时有效的临时链接，拿到后**立即下载**（`download_image`）。下载失败的报错写「结果图片下载失败」，不要说成 Key 错误。
- 参考图上限：模型名含 `qwen-image-2.1` 为 10 张，其余为 3 张（`max_ref_images`）。超出的部分截掉，并在结果里返回 warning。
- 比例对应的出图尺寸见 `SIZES`。目前只实测过 3:4 和 9:16，其余比例如果被接口拒绝，就在这里改。

### 5.5 AI 识别填入（`training_extract.py` + `extract_request`）

1. `read_document(name, blob)`：
   - `.txt` 和 `.md`：先按 UTF-8（带 BOM 也可）解码，失败再按 GB18030 解码。
   - `.docx`：用 `zipfile` 读 `word/document.xml`，按段落提取文字（表格里的段落也会读到），**不依赖 python-docx**。
   - `.doc` 和 PDF 直接拒绝，并在提示里说明怎么处理。
2. 原文超过 `EXTRACT_MAX_CHARS = 20000` 字时截断，并返回 `truncated: true`。
3. `extract_training()`：
   - 请求 `chat_url(base_url)`，即与生图同一个百炼域名下的 `/compatible-mode/v1/chat/completions`。
   - 参数为 `response_format: json_object`、`enable_thinking: false`（结构化输出要求非思考模式）、`temperature: 0.1`。
   - system 提示词里写了字段说明、今天的日期和「不要编造」等规则。**想提高识别质量，主要改 `_system_prompt()`**。
4. `normalize_training()`：把模型返回的结果规整到表单能接受的范围，包括选项白名单、日期和时间格式、长度上限（`LIMITS`，与前端输入框的 `maxlength` 一致）、最多 6 位讲师和 8 条课程。**模型返回什么都不会让表单出错**，改表单字段时要同步改这里。

### 5.6 错误与 Key 脱敏

上游 HTTP 错误统一交给 `http_error_message(exc, key)` 处理：生成中文提示，并把 Key 替换成 `[REDACTED]`。Key 不写入 manifest、`prompt.txt`、日志或 localStorage。**新增上游调用时，也要走这个函数**。

## 6. 前端

### 6.1 模块分工

| 文件 | 职责 | 对外提供 |
| --- | --- | --- |
| `training-prompt.js` | 表单值 → 培训海报提示词，纯函数 | `TrainingPoster.compile(values, {ratio, provider, maxRefImages}) → {prompt, references}`，以及 `example()`、`defaultSpeaker(i)`、`POSES`、`OUTFITS`、`AUDIENCES`、`FORMATS`、`LECTURER_MODES` |
| `training-form.js` | 培训信息弹窗的 DOM 和状态，肖像压缩，AI 识别面板 | `TrainingForm.mount / read / write / state / restore / persist / photo / photoCount / summary / setRefLimit / setExtractor / mergeExtracted` |
| `punk-cover.js` | 封面风格提示词 | `PunkCover.compile(style, title, context, ratio)` |
| `config.js` | 本机默认 Key | `StudioConfig.ready` |
| `app.js` | 其余全部：品类、弹窗开关、API 设置、提交、素材库、画布与图层编辑器 | — |

`index.html` 里脚本的加载顺序有依赖关系：`punk-cover → training-prompt → config → training-form → app`。

### 6.2 品类（`app.js` 顶部）

```js
PURPOSE_RATIO = {cover:'5:2', training:'3:4', free:'auto'}            // 默认比例
PROMPT_IDS    = {cover:'cover-prompt', training:'generate-prompt', free:'free-prompt'}  // 各品类独立的提示词框
DIALOG_IDS    = {cover:'cover-dialog', training:'training-dialog'}    // 自由创作没有设置弹窗
```

每个品类有自己的提示词框。切换品类时，只有共用的「画面比例」下拉需要通过 `ratioDrafts` 保存和恢复。

### 6.3 提示词的一致性（最容易改出问题的部分）

核心约束：**提示词里写的讲师肖像，必须和实际发给模型的肖像一致**；**用户手改过的提示词不能被悄悄覆盖**。

- `lastCompiled[category] = {prompt, ratio, provider, maxRefImages}`：记录弹窗上一次拼出的提示词，以及拼的时候用的生图设置。
- `isHandEdited(current, last)`：判断提示词框里的内容是否和上次拼出的不一样，即用户是否手改过。
- 弹窗保存时，如果用户手改过，先 `confirm` 再覆盖。
- 生图接口、模型或比例变化时由 `resyncPrompts()` 处理：
  - 没手改过：直接重新拼。
  - 手改过：把这个品类加进 `staleCategories`（Map，值是提示原因），提示词上方显示「重新拼装」提示条。
- 从素材库载入历史提示词时，如果和表单拼出的不一样，也标记为 stale。
- `confirmStale()`：提示条还在时点「生成」，先弹窗确认。
- `jobPayload()`：讲师肖像**按当前表单重新 compile 一次**，用返回的 `references` 下标去取照片。不要另外写一套「该发哪些肖像」的判断逻辑。
- 封面提示词与生图接口无关，所以只在比例变化时重拼（见 `stampMatches`）。

### 6.4 弹窗

- 打开时保存快照（`dialogSnapshot`）。「取消」、✕、Esc 都恢复快照。
- 「保存」时调用 `compileFor(category)`，出错就在弹窗内显示，不关闭弹窗。
- 弹窗是模态的，打开期间页面其他部分不能操作。所以弹窗里需要 Key 时，只能提示用户先关闭弹窗，不能去打开 API 设置面板。
- 封面风格选择器：隐藏的 `#style-select` 是唯一的数据来源，图片网格只是它的一个视图（`renderStyleGrid` / `syncStyleGrid`）。

### 6.5 浏览器存储

| localStorage 键 | 内容 |
| --- | --- |
| `poster-v2-training` | 培训表单的文字字段，**不含肖像** |
| `poster-v2-gen` | 生图接口、生图模型、Base URL、文本模型，**不含 Key** |

Key 只保存在页面内存里，刷新后清空；如果项目根目录有本机 Key 文件，启动时会自动填入。

### 6.6 页面约定

- 配色变量在 `style.css` 顶部的 `:root` 里，是暖灰底配近黑色主色。变量名 `--green` 是历史遗留，现在的值是近黑色。
- 黄色和红色只用于提醒和报错（`#fbf3d9`、`#f6e3df` 等），不要拿来做装饰。
- 画布上选中图层的框用蓝色 `#2443e5`（写在 `app.js` 里），深色海报上也看得清。

## 8. 常见改动怎么做

- **加一个品类**：
  1. 在 `index.html` 加品类按钮和提示词框。
  2. 在 `PURPOSE_RATIO`、`PROMPT_IDS` 里加一项；需要设置弹窗的话，再加 `DIALOG_IDS`、`SETTINGS_LABEL` 和对应的 `<dialog>`。
  3. 在 `compileFor()` 里加编译分支。
  4. 在服务端的 `PURPOSES` 和 `qwen_client.AUTO_RATIO` 里加上这个品类。
- **给培训表单加字段**：需要同步改五处：`training-form.js` 的 `skeleton / read / write / mergeExtracted`；`training-prompt.js` 的 `compile` 和 `example`；`training_extract.py` 的 `normalize_training`、`LIMITS` 和 `_system_prompt`；再给 `test_training.cjs` 和 `test_extract.py` 补测试。
- **换生图或文本模型的默认值**：改 `index.html` 里输入框的 `value`、`app.js` 的 `QWEN_DEFAULTS`，以及 README 里的默认值说明。
- **接其他服务商**：
  - 生图：在 `qwen_client.request_image` 旁边写一个新函数，在 `run_job` 里按 `provider` 分发，同时把 `validate_job_payload` 的 provider 白名单和前端 API 设置一起扩展。
  - 拆层：目前只有 MaaS 的 `ming-image-0.1-design-layer` 能用。
- **换「载入示例」**：把原图、各图层和 ZIP 放进 `static/`，再改 `loadExample()` 里的图层数量、`sampleNames` 和提示文案。

## 9. 编码与平台注意事项

- 目标环境是**中文 Windows**。所有文本文件读写都要显式写 `encoding='utf-8'`。原版 Cover Studio 就是因为 manifest 按 GBK 写入、按 UTF-8 读取，导致素材库读不出来。
- `启动.bat` 必须是 CRLF 换行，并包含 `chcp 65001`。
- 路径里有中文，用 Git Bash 调 `cmd` 时可能出现乱码，测试 bat 文件时用 PowerShell 的 `Start-Process`。
