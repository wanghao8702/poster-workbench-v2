# 开发规范

## 硬性约束

这些约束背后都有原因，打破之前先找项目负责人确认。

| 约束 | 原因 |
| --- | --- |
| 后端只用 Python 标准库，不引入 pip 依赖 | 目标用户的电脑上只装了 Python，没有开发环境 |
| 前端不引入框架、构建工具或第三方库 | 双击就能运行，不需要构建步骤 |
| 服务只监听 `127.0.0.1`，保留 `local_request()` 校验 | 防止局域网或其他网页调用本机服务、盗用 Key |
| 不写内联 `style="…"` 或内联 `<script>` | 页面安全策略禁止，写了也不生效 |
| Key 不写入任何文件、日志或 localStorage | 隐私和安全 |
| 上游 HTTP 错误统一交给 `http_error_message()` 处理 | 统一中文提示和 Key 脱敏 |
| 判断该发哪些讲师肖像，只能用 `TrainingPoster.compile().references` | 保证提示词里写的和实际发送的一致 |
| 不在用户不知情时覆盖手改过的提示词 | 产品承诺，见 [技术架构 · 提示词一致性的状态模型](技术架构.md#提示词一致性的状态模型) |
| Punk 只用 `v1.0.0-mit` 版本的内容 | 后续版本的许可不同 |

## 编码与平台

- 目标环境是**中文 Windows**。读写文本文件时一律写明 `encoding='utf-8'`；读取用户上传的文本时，要兼容 GBK（目前的做法是先按 UTF-8 解码，失败再按 GB18030）。
- `启动.bat` 必须是 CRLF 换行，并在开头执行 `chcp 65001`。
- 路径里有中文。用 Git Bash 调 `cmd` 时会乱码，测试 bat 文件时改用 PowerShell 的 `Start-Process`。
- 在 Windows 终端里用 Python 打印中文会乱码，调试时加环境变量 `PYTHONIOENCODING=utf-8`。

## 代码风格

- **跟随文件现有的风格。** `app.js` 和 `training-form.js` 沿用 Cover Studio 的紧凑写法（单空格缩进、一行多个语句），新代码保持一致，不要只格式化你改的那一段。
- 函数前用一行英文注释说明**为什么**，不复述代码做了什么。
- 所有面向用户的文案用简体中文，报错要说清楚原因和下一步该怎么做，例如「请另存为 .docx 或直接粘贴文字」。
- 输入长度限制要前后端一致：前端输入框的 `maxlength` 必须和 `training_extract.LIMITS` 对齐。
- 颜色用 `style.css` 顶部 `:root` 里的变量。黄色和红色只用于提醒和报错。

## 测试规范

### 原则

- **先写测试，看着它失败，再写实现。** 修 bug 时先写一个能复现问题的测试。
- 测试不调用真实接口，也不需要真实 Key。
- 提交前跑一遍全部测试：

```bash
python -m unittest test_server.py test_qwen.py test_extract.py
node test_training.cjs
node test_layers.cjs
node test_app.cjs
for f in static/*.js; do node --check "$f"; done
```

### 各测试文件负责什么

| 文件 | 覆盖范围 |
| --- | --- |
| `test_server.py` | 任务流程、Key 脱敏、素材库与旧记录兼容、参数校验、识别接口 |
| `test_qwen.py` | 协议判定、请求格式、参考图截断、下载报错 |
| `test_extract.py` | docx、txt、md 的读取，结果规整，文本模型请求格式 |
| `test_training.cjs` | 培训提示词：必填项、空字段、肖像上限、各种呈现方式 |
| `test_layers.cjs` | 图层编辑器：偏移、缩放、叠放顺序、导出、撤销 |
| `test_app.cjs` | 素材载入、请求体组装、生成前确认、清空画布、AI 识别结果合并 |

### mock 的写法

- 用 `unittest.mock.patch('<模块>.urllib.request.urlopen')` 模拟上游接口。
- `server`、`qwen_client`、`training_extract` 共用同一个 `urllib.request` 模块，后面的 patch 会覆盖前面的。同一个测试里要模拟多次调用时，**只用一个 patch，配合 `side_effect=[第一次返回, 第二次返回]`**。

### app.js 的切片标记

`test_layers.cjs` 和 `test_app.cjs` 是按字符串截取 `app.js` 的代码片段，放进 `vm` 里执行的。下面这些字符串在 `app.js` 里**必须唯一，且前后顺序不能变**：

例如，在别处再写一个 `const snapshot=`，图层撤销测试就会截到错误的代码。新加的局部变量换个名字即可。如果确实要改动这些标记，记得同步修改测试里的切片。

切片在 `vm` 里运行时，跨上下文的数组和对象不能直接用 `deepEqual` 比较，要先用 `JSON.parse(JSON.stringify(x))` 转一下（测试文件里已有 `plain()` 工具函数）。

### 浏览器检查

1. 另开一个端口启动服务，例如 `python server.py --port 8770`，不要影响正在使用的 8765。
2. 在页面里包装 `window.fetch`，拦截 `POST /api/jobs` 和 `/api/extract`，只核对请求体，返回一个假结果。**不要让请求真的发出去**：既会花钱，也会把肖像和文档内容发到外部。
3. 检查控制台没有报错。注意：直接往 `document` 派发键盘事件，会触发一条 `closest is not a function` 的报错。这是测试手法造成的，真实按键不会出现。

## 常见改动清单

### 加一个品类

1. `index.html`：加品类按钮（`data-purpose`）和对应的提示词框。
2. `app.js`：在 `PURPOSE_RATIO`、`PROMPT_IDS` 里加一项；需要设置弹窗的话，还要在 `DIALOG_IDS`、`SETTINGS_LABEL` 里加一项，并新增 `<dialog class="settings-dialog">`；在 `compileFor()` 里加编译分支。
3. 服务端：在 `server.PURPOSES` 和 `qwen_client.AUTO_RATIO` 里加上这个品类。
4. 补测试，更新接口文档和 README。

### 给培训表单加字段（五处要同步改）

1. `training-form.js`：`skeleton`（输入框）、`read`、`write`、`mergeExtracted`、`markFilled`。
2. `training-prompt.js`：`compile`（写进提示词）、`example`。
3. `training_extract.py`：`normalize_training`、`LIMITS`、`_system_prompt`（告诉模型提取这个字段）。
4. 测试：`test_training.cjs`、`test_extract.py`、`test_app.cjs`。
5. 文档：接口文档里的 `values` 和长度限制。

### 改识别效果

主要改 `training_extract._system_prompt()`。用 `../培训通知样例/` 里的 5 份样例对比修改前后的效果，每份样例的理想结果记录在问题待办里。如果要加新的规则约束，同时在 `normalize_training` 里兜底。

### 换默认模型

改 `index.html` 里输入框的 `value`，以及 `app.js` 的 `QWEN_DEFAULTS`（文本模型的兜底值写在 `TrainingForm.setExtractor` 的调用处），再同步更新 README 和接口文档。

### 接其他生图服务商

在 `qwen_client.request_image` 旁边写一个新函数，在 `run_job` 里按 `provider` 分发。同时修改 `validate_job_payload` 的 provider 白名单、前端 API 设置面板和 `genSettings()`。拆层目前只有 MaaS 能用。

### 换「载入示例」

把原图、各图层和 ZIP 放进 `static/`，命名为 `example.png`、`layer-NN.png`、`example-layers.zip`；然后修改 `loadExample()` 里的图层数量、`sampleNames` 和提示文案。

## 提交与发布

- 仓库是本地 git，没有远程仓库。每完成一个可以独立验证的改动，就提交一次。
- 提交信息格式：`类型: 简述`，类型用 `feat`、`fix`、`refactor`、`docs`、`copy`（只改文案）、`chore`。正文写清楚**为什么**这样改。
- 每次提交都要同步更新 [变更日志](变更日志.md)；解决了待办就更新 [问题待办](问题待办.md)。
- 改了 `server.py`、`qwen_client.py` 或 `training_extract.py` 之后，提醒使用者**重启服务**。
